# DepGuard

> Security scanners cry wolf — most dependency-vulnerability alerts are false alarms, and engineering
> teams burn days triaging them by hand. **DepGuard** is an AI agent that proves which alerts are
> actually real — citing the exact advisory evidence — and names the smallest safe upgrade.
> Every verdict is checked by a **100%-mechanical verifier**, so we can tell you *exactly* how often it's right.

## The real experiment

Dependency-alert triage over a frozen advisory corpus is *mechanically decidable* — a deterministic
pipeline (à la `osv-scanner`) already solves it without any LLM. That's precisely why it makes a good
testbed. DepGuard runs a **three-arm ablation**:

| Arm | What it is |
|---|---|
| `deterministic_script` | A plain, LLM-free pipeline — the honest baseline |
| `single_agent` | One ReAct agent with the same six typed tools |
| `multi_agent` | LangGraph supervisor → planner → retriever → tool worker → verifier |

All three arms emit the same [trajectory format](schemas/trajectory.schema.json) and are scored by the
same **4-predicate mechanical verifier** (no LLM judge in the correctness path), with paired-bootstrap
95% confidence intervals. The question being measured: **when does an agent add value over a solved
deterministic pipeline — and how would you even know?**

## How it works (design frozen in [DECISIONS.md](DECISIONS.md))

- **Input:** a pinned dependency manifest + scanner advisory alerts (npm, PyPI, crates.io, Go).
- **Per alert:** (a) is the pinned version *actually* inside the advisory's affected range?
  (b) the authoritative advisory + exact range-event evidence, (c) the minimal *published* safe
  upgrade version, grounded in the deps.dev version list.
- **Ground truth:** a frozen OSV + deps.dev snapshot (`corpus_snapshot_id` on every evidence row;
  the verifier refuses to score across snapshot mismatches). Six typed tools on a uniform
  `{ok, data, error}` envelope; tools never throw.
- **Caveat we state up front:** the widely-cited 71–90% scanner false-positive rates are driven
  mostly by *reachability* analysis, which DepGuard deliberately does not do. DepGuard addresses the
  version-range-containment slice of triage — the slice with mechanical ground truth.
